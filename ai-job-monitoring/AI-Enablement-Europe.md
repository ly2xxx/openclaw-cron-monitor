## Posted Column Convention

**All updates MUST populate the `Posted` column with a precise date (YYYY-MM-DD), not vague indications like '1 week ago' / '2 weeks' / '1 day'.**

**Rules:**
- Format: `YYYY-MM-DD` (e.g. `2026-07-27`).
- Source: derive from LinkedIn's `Listed X days ago` text using the scan date as anchor (scan date minus X days).
- For LinkedIn tags like `Reposted`, `Actively reviewing`, or any deviation from 'Listed X days ago', still record the **computed posting date** as the Posted value and add a note in the Status column.
- For jobs that show `Just now`, `Today`, `Yesterday`, or any non-numeric label that prevents computing a date, fall back to the scan date and add ` (LinkedIn gave no numeric ago)` to Status.
- If the Posted value was previously a vague ago-string, the next scan MUST overwrite it with a computed YYYY-MM-DD date.
- Daily scans: in the scan header summary, also report any job whose Posted value decreased as a repost signal.

**Why this matters:** date-based diffing lets us reliably detect reposts, flag stale listings, and compute time-in-market.


**Row Order (mandatory after every daily update):**
- The main table MUST be re-sorted by `Posted` DESC (newest first). Ties broken by Role ASC for stability.
- Historical scan notes (`## Daily Scan: YYYY-MM-DD - ...`) keep their chronological order unchanged; the rule applies only to the live `### All AI Roles by Company` table.
